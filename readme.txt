Shows in KIscore which AI crawlers visit your site and which visitors come from ChatGPT, Perplexity and other AI assistants.

== Description ==

KIscore measures how visible a brand is in AI answers. This plugin adds the traffic side: it reports page views from your WordPress server to KIscore, which keeps

* hits of AI crawlers such as GPTBot, ClaudeBot and PerplexityBot, and
* visits referred by AI assistants such as ChatGPT or Perplexity, recognised by referrer or `utm_source`.

Everything else is discarded. You see the results in the KIscore dashboard under Traffic Overview.

* No script and no cookie on your pages
* Reports are sent after the page is delivered (PHP-FPM, LiteSpeed) or with a one-second limit, and never break a page
* Query parameters other than `utm_*` never leave your server
* Requires a KIscore account

== Installation ==

1. Install and activate the plugin.
2. In the KIscore dashboard, open Settings → Traffic tracking → WordPress and copy the connection key.
3. In WordPress, open Settings → KIscore, paste the key and save.
4. Click "Check connection".

To keep the key out of the database, define it in `wp-config.php` instead:

`define( 'KISCORE_CONNECTION_KEY', '…' );`

An environment variable with the same name works as well. Site ID and tracking secret from plugin version 1.0 (`KISCORE_SITE_ID`, `KISCORE_TRACKING_SECRET`) keep working.

== Frequently Asked Questions ==

= My site runs behind a proxy, load balancer or CDN =

Then WordPress sees the proxy's address instead of the visitor's, and visits of different people can be counted as one. Behind Cloudflare the plugin reads the visitor IP from `CF-Connecting-IP` by itself. For other proxies, name the header that carries the visitor IP in `wp-config.php`, for example `define( 'KISCORE_CLIENT_IP_HEADER', 'X-Real-IP' );`. The settings page warns you when WordPress only sees a private address. Only a single, valid IP address is accepted, so lists such as `X-Forwarded-For` cannot be used.

= Does it work with page caching? =

Only for requests that reach WordPress. A page cache delivers a stored page before plugins load, so this plugin cannot report it. Without changes, KIscore would only see the one request per cache period that refills the cache. Emptying the cache does not help, the next request stores the page again.

Exclude the requests KIscore needs from the cache instead. Everyone else keeps getting cached pages. The AI crawlers to exclude are: `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `Claude-User`, `Claude-SearchBot`, `PerplexityBot`, `Perplexity-User`, `meta-externalagent`, `Meta-ExternalFetcher`, `MistralAI-User`, `DuckAssistBot`, `Amazonbot`, `CCBot`, `Bytespider`. Search engine crawlers such as Googlebot can stay cached.

* LiteSpeed Cache: under Cache → Excludes, add the crawlers to "Do Not Cache User Agents" and `utm_source` to "Do Not Cache Query Strings". Do not add `utm_source` to "Drop Query String".
* WP Rocket: under Advanced Rules, add the crawlers to "Never Cache User Agent(s)". WP Rocket ignores `utm_source` and serves the cached page; only its helper plugin "WP Rocket | Ignore Query Strings" removes `utm_source` from that list (do not add it to "Cache Query String(s)").
* WP Super Cache: under Settings → WP Super Cache → Advanced, add the crawlers to "Rejected User Agents" and a line `utm_source=` to "Rejected URL Strings". Leave "Tracking parameters" disabled.

Then empty the cache once, so pages stored before the change are no longer served.

To check the result, open `/?utm_source=test` twice in a private window. If the second view does not come from the cache (with WP Super Cache, the comment "Cached page generated by WP-Super-Cache" at the end of the page source is missing), the request reaches WordPress.

Visits referred by an AI assistant without `utm_source`, recognised only by their referrer, still receive cached pages and are not reported. A CDN that caches HTML needs the same exclusions in its own settings.

= Which requests are reported? =

Frontend GET requests for HTML pages. Not reported: the admin area, REST API, AJAX, cron, feeds, robots.txt, previews, redirects, browser prefetches and requests without a valid visitor IP.

= How do I test it? =

Open any page of your site with `?utm_source=chatgpt.com&utm_campaign=kiscore-integration-test`. The visit then appears in KIscore under KI-Verweise.

== External services ==

This plugin sends data to the KIscore tracking API at `https://api.kiscore.ai/track/<site-id>`, operated by KIscore (https://kiscore.ai). It is needed to show AI crawler visits and AI referrals in your KIscore account.

For every reported page view it sends: the path with its `utm_*` parameters, the visitor's user agent, the referrer and the visitor IP, together with the site ID and tracking secret from your connection key. For human visitors KIscore stores only a daily hash of the IP, never the address; hits of AI crawlers are stored with their IP. Nothing is sent before you enter a connection key.

The "Check connection" button sends one request without visitor data.
